# MITgcm: Inputs and Modeling

## High-Signal Playbook

### Route conditions
- Use this skill for forcing files, namelist configuration, package activation, and binary input generation (docs: `verification/global_with_exf/README.md`, `verification/seaice_obcs/README.md`, `doc/examples/plume_on_slope/plume_on_slope.rst`).
- Route compile/toolchain issues to `mitgcm-build-and-install`.
- Route algorithm scheme/stability math to `mitgcm-theory-and-methods`.
- Route output interpretation/comparison to `mitgcm-analysis-and-output`.

### Triage questions
- Which forcing path is used: EXF interpolation, bulk formulas, or prescribed boundary fields?
- Which packages must be active (`exf`, `obcs`, `seaice`, `bulk_force`, `nonHydrostatic`), and where are they enabled (`packages.conf`, `data.pkg`, CPP flags)?
- Are binary inputs pre-existing or generated by scripts (`gendata.m`, `mk_input.m`, `mk_tides.m`)?
- Does input grid geometry satisfy EXF interpolation assumptions (Cartesian input, periodic x, full y coverage)?
- Are open boundary options required (`useSeaiceSponge`, `useOBCStides`) with matching files in `data.obcs`?
- Is this forward setup or an adjoint/state-estimation setup (`input_ad`, `data.ecco`, `data.ctrl`)?

### Canonical workflow
1. Start from the closest verification configuration (`global_with_exf`, `seaice_obcs`, `tutorial_plume_on_slope`, `tutorial_rotating_tank`).
2. Activate required packages in compile-time and runtime configs (docs: `doc/examples/plume_on_slope/plume_on_slope.rst`).
3. Define forcing-grid and field metadata (`*_lon0`, `*_lat0`, `*_lon_inc`, `*_lat_inc`, `*_nlon`, `*_nlat`) for EXF interpolation (docs: `verification/global_with_exf/README.md`).
4. Generate or stage binary inputs with documented scripts and file names (docs: `verification/seaice_obcs/README.md`, `doc/examples/plume_on_slope/plume_on_slope.rst`).
5. Run short forward test and inspect monitor/diagnostics and reference output.
6. For estimation/adjoint workflows, configure `data.ecco`/control terms and validate cost-function outputs (docs: `doc/ocean_state_est/ocean_state_est.rst`).

```fortran

# secondary: useOBCStides=.TRUE. with mk_tides.m-generated files
```

### Pitfalls and fixes
- EXF interpolation domain mismatch: y must cover full output grid; x periodic padding required (1 point bilinear, 2 points bicubic) (docs: `verification/global_with_exf/README.md`).
- Tidal OBCS file naming mismatch after PR #752: apply documented rename/update workflow (`update_TideFileName.sed`) in `data.obcs` (docs: `verification/seaice_obcs/README.md`).
- `bulk_force` without required atmospheric fields from `data.blk` leads to incorrect flux pathway; ensure required files are provided (docs: `doc/phys_pkgs/bulk_force.rst`).
- Expecting `bulk_force` to run independently of sea-ice pathway: current setup assumes `pkg/thsice` integration (docs: `doc/phys_pkgs/bulk_force.rst`).
- Nonhydrostatic plume setup built without `ALLOW_NONHYDROSTATIC` or runtime `nonHydrostatic=.TRUE.` and `useOBCS=.TRUE.` (docs: `doc/examples/plume_on_slope/plume_on_slope.rst`).
- Misinterpreting modeled vs observational cost outputs in state estimation; confirm `gencost_*` naming, averaging period, and mask files (docs: `doc/ocean_state_est/ocean_state_est.rst`).

### Convergence and validation checks
- Verify startup package list confirms required modules are compiled and used.
- Check monitor and diagnostics lists include expected package outputs (e.g., sea-ice/OBCS-specific streams).
- Confirm solver behavior (`cg2d` residual/iterations) is stable relative to configured targets.
- For conservative tracer setups, use provided conservation checks where available (e.g., `verification/advect_xz/input.nlfs/check_conserve_TS.txt`).
- Validate against reference `results/output*.txt` for the chosen verification branch.
